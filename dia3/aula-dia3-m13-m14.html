1 — Componente: função que devolve UI

No M11 vocês viram: um componente é uma função que retorna JSX (UI descrita em JavaScript).

Componente funcional (M11)

Nome do componente: PascalCase (maiúscula no início). Sempre.

Paralelo com o back

No ASP.NET (M5), uma action devolve IActionResult.

No React (M11), o componente devolve um pedaço de interface.

Entra dado → sai representação.

2 — Estado: useState e re-render

No M12: variável comum muda o valor, mas a UI não atualiza. useState registra estado reativo — ao chamar o set…, o React faz re-render do componente.

useState — valor atual + setter (M12)
const [nome, setNome] = useState(""); // nome → valor atual do estado // setNome → única forma correta de atualizar setNome("Ana Mucavel"); // agenda re-render nome = "Ana"; // ERRADO: UI não muda

Regra (M12)

Não atribuam direto em nome.

Sempre setNome(…).

Parecido com: no C# você não altera o banco “na mão” — passa pelo Repository (M8).

3 — Formulário controlado

No HTML clássico o input guarda o texto sozinho. No React controlado (M13), o estado é a fonte da verdade: value exibe e onChange atualiza.

value + onChange (formulário controlado)
<input value={nome} onChange={(e) => setNome(e.target.value)} />

Só value → input travado. Só onChange → estado e tela desalinhados. Os dois juntos.

Por quê

Com o estado sincronizado dá para validar, limpar e desabilitar o botão.

O JSON do POST (M5) sai desse mesmo estado.

5b — fetch na prática (2 passos)

  1. Chamar — manda o pedido e espera a resposta
  2. Ler o JSON — transforma o texto em objeto JavaScript
Exemplo — listar contribuintes
const r = await fetch("http://localhost:5088/api/contribuintes"); // r = “envelope” (status 200, 400, 401…) if (!r.ok) throw new Error("A API recusou"); const lista = await r.json(); // lista = [{ id, nome, nuit }, …]
Armadilha: fetch não quebra sozinho em 400/500. Tem que olhar r.ok — igual olhar o status no Swagger.

Não espalhamos fetch nas páginas.

6 — useEffect: efeito após o render

Chamar fetch no corpo do componente (M12) gera loop: busca → re-render → busca de novo.

useEffect agenda o efeito depois do render, controlado pela lista de dependências.

Dependências (M12)
useEffect(() => { // GET na API aqui }, []); // [] = ao montar a tela useEffect(() => { ... }, [id]); // de novo se id mudar

Erro clássico

Esquecer o [] → dezenas de GETs (loop).

Dois GETs iguais = Strict Mode no dev (normal).

Em produção fica um GET só.

7 — Os quatro estados da tela

Toda tela que consome API (M12/M13) precisa tratar quatro estados de UI. Implementar só o “sucesso” gera tela frágil.

EstadoQuandoO que o atendente vê

Vazio ≠ erro

Lista vazia é resposta normal: 200 com [].

Tela em branco faz o atendente achar que quebrou.

Os quatro na lista. Formulário e ficha usam o mesmo espírito (carregando / erro / vazio).

10 — useParams: o id na URL

A rota /contribuintes/:id declara um parâmetro dinâmico. useParams lê esse valor da URL.

Parâmetro de rota (como {id} no M5)

Sempre chega como string. No fetch vai direto na URL — igual ao {id:int} do Controller.

Manhã 6a — o que é ...opcoes?

req tem dois parâmetros: a URL (caminho) e um pacote extra (opcoes). Os três pontinhos juntam esse pacote ao que o fetch sempre manda.

Quem chama2º parâmetro (opcoes)O fetch recebe
GET — listar(vazio)só headers JSON
POST — criarmethod: "POST"
body: "…json…"		headers + method + body

Sem os ...

fetch veria um objeto opcoes dentro de outro — errado.

Com ...opcoes

As chaves “desembrulham” e viram irmãs do headers — certo.

Frase de sala: “Header fixo para todo mundo; ...opcoes traz o verbo e o corpo quando precisar.” Não precisam decorar spread — só copiar igual ao slide 6.

3 — O que é um JWT

É um texto longo com três pedaços separados por ponto.
